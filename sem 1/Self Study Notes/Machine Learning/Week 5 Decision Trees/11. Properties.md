# Decision Trees vs. Regression Trees

**Decision trees** form the overarching family of tree-based models that recursively partition feature space into axis-aligned regions, while a **regression tree** is a decision tree specialized for predicting continuous numerical targets rather than discrete class labels. In everyday machine learning usage, "decision tree" often refers to a **classification tree** when contrasted with a regression tree.

---

## Core Comparison

| Dimension | Classification Tree ("Decision Tree") | Regression Tree |
| :--- | :--- | :--- |
| **Target Variable ($y$)** | Discrete / categorical class labels (e.g., $\text{spam}$ vs. $\text{non-spam}$, or `g` vs. `b`[cite: 2]) | Continuous numerical values (e.g., house price, temperature, salary) |
| **Leaf Prediction** | Majority class (or class probability distribution) in the leaf region | Mean (or median) of target values of training samples in the leaf region |
| **Split / Impurity Criteria** | **Information Gain** (via Shannon entropy), **Gini Impurity**, or misclassification error | **Variance reduction** / **Mean Squared Error (MSE)** or **Mean Absolute Error (MAE)** |
| **Output Space** | Partitioned into discrete class assignments across regions | Piecewise-constant step function over rectangular regions |

---

## How Each Works

### 1. Classification Trees (Impurity & Information Gain)
* Splits aim to increase **class purity** inside each child node.
* Using weighted entropy and **Information Gain**, a threshold split $x \le v$ on dataset $\mathcal{D}$ of size $N$ into left ($\mathcal{D}^{(\text{L})}$) and right ($\mathcal{D}^{(\text{R})}$) subsets evaluates:

$$\mathrm{I}(x \le v) = N \cdot \mathrm{H}(V) - N^{(\text{L})} \cdot \mathrm{H}\left(V^{(\text{L})}\right) - N^{(\text{R})} \cdot \mathrm{H}\left(V^{(\text{R})}\right)$$

* A split that isolates a single class in a child region drives that region's entropy down toward $0$, yielding higher information gain.
* At inference time, a sample landing in a leaf receives the most frequent class in that leaf (or estimated class probabilities).

### 2. Regression Trees (Error / Variance Reduction)
* Instead of class frequencies, each region $R_m$ predicts a constant numerical value—typically the sample mean $\hat{y}_{R_m} = \frac{1}{|R_m|} \sum_{i \in R_m} y_i$.
* Splits choose the feature and cut point that minimize prediction error across resulting regions—commonly **Sum of Squared Errors (SSE) / MSE**:

$$\text{SSE} = \sum_{i \in R^{(\text{L})}} \left(y_i - \hat{y}_{R^{(\text{L})}}\right)^2 + \sum_{i \in R^{(\text{R})}} \left(y_i - \hat{y}_{R^{(\text{R})}}\right)^2$$

* Because each leaf outputs a constant value, a regression tree produces a **step function**—it cannot extrapolate smoothly beyond the range of training target values without additional models (such as linear model trees).

---

## Shared Characteristics & Practical Trade-offs

* **Interpretability**: Both produce transparent, human-readable if-then rules and handle non-linear relationships and feature interactions naturally without requiring feature scaling.
* **Overfitting**: Unpruned trees of either type can memorize training noise; depth limits, minimum leaf sample counts, or cost-complexity pruning are standard remedies.
* **Ensemble Extensions**: Both serve as base learners for **Random Forests** and **Gradient Boosted Decision Trees (GBDTs)** (such as XGBoost, LightGBM, and CatBoost), where ensembling significantly reduces variance and improves generalization.

> [!NOTE]
> Classification trees optimize **purity / information** over discrete labels, whereas regression trees optimize **squared/absolute error** over continuous values.

# Computational Complexity of CART

This note covers the training (fitting) and inference (prediction) time complexity of **CART** (Classification and Regression Trees) with $N$ data points, $M$ features (dimensionality), and axis-aligned splits.

---

## Finding Splits & Amortized Analysis

* **Setup**: $N$ data points of dimensionality $M$ using axis-aligned splits.
* **Single feature (pre-sorted)**: Finding the best split value for a given feature takes $\mathcal{O}(N)$ time.
  * **Amortized analysis**: $\mathcal{O}(N)$ to initialize all data points into the left child, plus $\mathcal{O}(1)$ per step when moving one data point from the left child to the right child at a time.
* **Across all features at the root**: Checking each of the $M$ features takes $\mathcal{O}(M \cdot N)$ time.
* **Recurrence structure**: Let $T(N)$ denote the total time for a complete subtree with $N$ data points; it combines the split cost at the current node/root with the costs of the child subtrees.

> [!NOTE]
> The $\mathcal{O}(N)$ split scan per feature assumes the feature values are already pre-sorted. (If sorting happens per node rather than pre-sorted once, an extra $\log N$ factor can appear in standard implementations.)

---

## Best Case: Balanced Trees

When splits repeatedly divide the data roughly in half:

* **Fitting recurrence**:

$$T(N) = \mathcal{O}(M \cdot N) + 2 \cdot T\left(\frac{N}{2}\right)$$

* **Total fitting time**: $\mathcal{O}(M \cdot N \log N)$, because each of the $\approx \log N$ tree levels processes $\mathcal{O}(M \cdot N)$ work across all nodes at that depth.
* **Prediction time**: $\mathcal{O}(\log N)$, as a query traverses down a balanced tree of height $\mathcal{O}(\log N)$.

---

## Worst Case: Skewed / Degenerate Trees

When splits peel off only **one data point at a time** (leaving $N - 1$ points on the other side):

* **Fitting recurrence**:

$$T(N) = \mathcal{O}(M \cdot N) + T(N - 1)$$

* **Total fitting time**: $\mathcal{O}(M \cdot N^2)$ (summing $\mathcal{O}(M \cdot k)$ for $k = N, N-1, \dots, 1$).
* **Prediction time**: $\mathcal{O}(N)$, since the tree depth can degenerate to $\mathcal{O}(N)$.

---

## Summary Table

| Scenario | Tree Shape | Fitting (Training) Time | Prediction (Inference) Time |
| :--- | :--- | :---: | :---: |
| **Best Case** | Balanced ($\approx \log N$ levels) | $\mathcal{O}(M \cdot N \log N)$ | $\mathcal{O}(\log N)$ |
| **Worst Case** | Skewed (1 point split off per step) | $\mathcal{O}(M \cdot N^2)$ | $\mathcal{O}(N)$ |
