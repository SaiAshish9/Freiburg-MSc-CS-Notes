# Gradients and Optimization Algorithms: Batch vs. Stochastic Gradient Descent

> [!NOTE] Overview
> These slides break down the exact gradient equations for **Linear vs. Logistic Regression** and formalize the two primary optimization algorithms used to minimize loss: **Standard Gradient Descent (Batch GD)** and **Stochastic (Mini-Batch) Gradient Descent**.

---

## Part 1: Gradients for Linear vs. Logistic Regression

To update weights via gradient descent, we need the partial derivative (gradient) of the loss function $J(w)$ with respect to the weight vector $w$.

### 1. Linear Regression Gradient
* **Loss Function (MSE)**: $J(w) = \sum_{i=1}^{N} (y_i - f(x_i; w))^2$
* **Gradient**: 
  $$\frac{\partial J(w)}{\partial w} = \sum_{i=1}^{N} -2(y_i - f(x_i; w)) x_i$$
* **Interpretation**: The update direction is driven by the residual error $(y_i - f(x_i; w))$ multiplied by the input features $x_i$.

### 2. Logistic Regression Gradient
* **Loss Function (Binary Cross-Entropy)**: $J(w) = \sum_{i=1}^{N} \left[ -y_i \log(h_w(x_i)) - (1 - y_i) \log(1 - h_w(x_i)) \right]$
* **Gradient**:
  $$\frac{\partial J(w)}{\partial w} = \sum_{i=1}^{N} - (y_i - h_w(x_i)) x_i$$
* **Key Insight**: Despite logistic regression using a non-linear sigmoid activation and a logarithmic loss function, its gradient simplifies to a form nearly identical to linear regression: $(y_i - \text{prediction}) \times x_i$. This elegance is a result of the sigmoid function's derivative canceling out terms during the chain rule.

## Part 2: Standard Gradient Descent (Batch GD)

The ultimate objective is to find the optimal parameters $w^* \in \mathbb{R}^K$ that minimize the objective function across the entire dataset $\mathcal{D}$:
$$w^* := \arg\min_w J(\mathcal{D}, w)$$

### Algorithm 1: Gradient Descent Optimization
* **Input**: Full dataset $\mathcal{D}$, learning rate $\eta \in \mathbb{R}_+$, number of iterations $I \in \mathbb{N}_+$
* **Steps**:
  1. Initialize weights randomly: $w \sim \mathcal{N}(0, \sigma^2)$
  2. For $1, \dots, I$ iterations:
     $$w \leftarrow w - \eta \frac{\partial J(\mathcal{D}, w)}{\partial w}$$
  3. Return $w$

> [!WARNING] Limitation of Batch GD
> Because it computes the gradient using the **entire dataset** $\mathcal{D}$ in every single step, a single iteration can become computationally prohibitive when working with millions of samples.

---

## Part 3: Stochastic / Mini-Batch Gradient Descent

To solve the scalability bottleneck of Batch GD, we divide the dataset into $R$ non-overlapping partitions (mini-batches) $\mathcal{D}_r$:
$$\mathcal{D} = \bigcup_{r=1}^{R} \mathcal{D}_r \quad \text{where } \forall i \neq j, \, \mathcal{D}_i \cap \mathcal{D}_j = \emptyset$$

The total loss is decomposed into the sum of mini-batch losses:
$$J(\mathcal{D}, w) := \sum_{r=1}^{R} J(\mathcal{D}_r, w) := \sum_{r=1}^{R} J_r$$

### Algorithm 2: Stochastic Gradient Descent Optimization
* **Input**: Partitioned dataset $\mathcal{D} = \bigcup_{r=1}^{R} \mathcal{D}_r$, learning rate $\eta$, iterations $I$
* **Steps**:
  1. Initialize weights: $w \sim \mathcal{N}(0, \sigma^2)$
  2. For $1, \dots, I$ iterations:
     * For each mini-batch $r \in \{1, \dots, R\}$ in **random order**:
       $$w \leftarrow w - \eta \frac{\partial J_r}{\partial w}$$
  3. Return $w$

> [!TIP] Why Mini-Batch SGD Dominates Deep Learning
> * **Speed**: Updates weights $R$ times per epoch rather than waiting until the entire dataset is processed.
> * **Escape Routes**: The stochastic noise introduced by evaluating subsets helps the optimizer escape shallow local minima or saddle points.

# Gradient Descent (GD) vs. Stochastic Gradient Descent (SGD)

> [!NOTE] Core Concept
> Both **Gradient Descent** and **Stochastic Gradient Descent** are iterative optimization algorithms used to find the model parameters ($w$) that minimize a loss function $J(w)$[cite: 6, 8]. The fundamental difference lies in **how much training data is used to compute the gradient before updating the weights**.

---

## 1. Standard Gradient Descent (Batch GD)

### How It Works
* **Full-Dataset Evaluation**: In every single iteration, the algorithm processes the **entire dataset** $\mathcal{D} = \{(x_i, y_i)\}_{i=1}^N$ to compute the exact gradient of the overall loss function.
* **Update Rule**:
  $$w \leftarrow w - \eta \frac{\partial J(\mathcal{D}, w)}{\partial w}$$
  *(Weights are updated only **once** per full pass over the dataset)*.

### Pros & Cons
* **Pros**: 
  * Produces a stable, smooth convergence path directly toward the minimum.
  * Guarantees convergence to the global minimum for convex loss functions.
* **Cons**: 
  * **Slow and memory-heavy** on large datasets. If you have 10 million training examples, computing one single weight update requires evaluating all 10 million examples first.

---

## 2. Stochastic Gradient Descent (SGD)

> [!TIP] Terminology Note
> Strictly speaking, pure SGD updates weights using **1 single random sample** at a time. In modern machine learning (and in your course slides), "SGD" typically refers to **Mini-Batch SGD**, which updates weights using small random subsets of data.

### How It Works
* **Partitioned Evaluation**: The dataset $\mathcal{D}$ is split into $R$ smaller, non-overlapping subsets (mini-batches) $\mathcal{D}_r$.
* **Update Rule**: In each epoch (full pass), the algorithm shuffles the mini-batches and updates the weights **after each individual mini-batch** $r$:
  $$w \leftarrow w - \eta \frac{\partial J_r}{\partial w}$$
  *(Weights are updated **$R$ times** per pass over the dataset)*.

### Pros & Cons
* **Pros**: 
  * **Fast and scalable**: Computes updates using small chunks of data, fitting easily into GPU/CPU memory.
  * **Escapes local minima**: Because each mini-batch is only an *approximation* of the true gradient, the path to the minimum is noisy and zig-zags. This randomness helps bounce the model out of shallow local minima or saddle points in non-convex landscapes.
* **Cons**: 
  * Never settles completely still at the exact minimum; it oscillates closely around it unless the learning rate $\eta$ is gradually decayed.

---

## 3. Quick Comparison

| Feature | Gradient Descent (Batch GD) | Stochastic Gradient Descent (Mini-Batch SGD) |
| :--- | :--- | :--- |
| **Data per Update** | Entire dataset ($\mathcal{D}$) | One mini-batch ($\mathcal{D}_r$) or single sample |
| **Updates per Epoch** | $1$ update | $R$ updates (number of mini-batches) |
| **Gradient Accuracy** | Exact gradient of total loss | Noisy approximation of total loss |
| **Convergence Path** | Smooth, direct trajectory | Noisy, zig-zagging trajectory |
| **Computational Cost** | High per step; slow on big data | Low per step; fast and memory-efficient |

# Why Use Gradient Descent & Stochastic Gradient Descent?

> [!NOTE] Core Purpose
> Gradient Descent and Stochastic Gradient Descent (SGD) are the primary optimization workhorses of machine learning. They are used because **real-world models and massive datasets cannot be solved using simple, direct formulas.**

---

## 1. Why Use Gradient Descent (GD)?
When training machine learning models, our goal is to find the weights ($w$) that minimize the loss function $J(w)$. Gradient descent is used for several critical reasons:

* **Solves Models Lacking Closed-Form Solutions**: While simple linear regression has a neat matrix formula ($w = (X^T X)^{-1} X^T y$), models like **logistic regression** and **deep neural networks** have non-linear activation functions (like the sigmoid or ReLU) whose cost functions have no direct algebraic solution. Gradient descent provides an iterative path to the minimum.
* **Systematic Learning**: Instead of randomly guessing weights, gradient descent uses calculus (derivatives) to guarantee that every step moves the model in the direction of reduced error.
* **Flexibility**: The same core optimization logic applies universally across linear models, logistic regression, and multi-layer neural networks.

---

## 2. Why Use Stochastic Gradient Descent (SGD)?
While standard Batch Gradient Descent works well, it becomes impractical as datasets grow. SGD (specifically mini-batch SGD) is used to overcome major computational bottlenecks:

* **Massive Scalability**: If you have 100 million training examples, standard gradient descent requires computing predictions and errors across all 100 million rows just to take *a single step*. SGD breaks the data into smaller mini-batches, allowing the model to start updating weights almost immediately.
* **Memory Efficiency**: Loading an entire massive dataset into RAM or GPU memory simultaneously causes out-of-memory crashes. Mini-batch SGD processes data in small, manageable chunks.
* **Escaping Local Minima and Saddle Points**: Because mini-batch updates introduce slight "noise" (since a small sample only approximates the true gradient), the optimization trajectory zig-zags. This randomness is actually a superpower—it frequently helps the model bounce out of shallow local minima or flat saddle points where batch gradient descent might otherwise get stuck.
* **Online Learning**: SGD allows models to update continuously as new data streams in, without needing to re-run optimization over the entire historical dataset.

---

> [!TIP] Summary
> We use **Gradient Descent** because complex loss landscapes require iterative descent rather than direct formulas, and we use **Stochastic Gradient Descent** to make that descent fast, memory-efficient, and capable of scaling to modern big data.

# Parallel Processing in Stochastic Gradient Descent (SGD)

> [!NOTE] Short Answer
> **SGD is inherently sequential across iterations**, but it is **highly parallelizable within each mini-batch**. This dual nature is why mini-batch SGD is the foundation of modern GPU-accelerated deep learning.

---

## 1. Across Iterations: Inherently Sequential
* **The Dependency**: In both standard Gradient Descent and SGD, the weight update rule relies on the current weights:
  $$w^{\text{(next)}} \leftarrow w^{\text{(prev)}} - \eta \frac{\partial J_r}{\partial w}$$
* **Why it's sequential**: You cannot compute step $t+1$ until step $t$ has updated the weights. Each iteration depends on the state produced by the previous one, meaning you cannot run the sequence of time steps in parallel.

---

## 2. Within Mini-Batches: Highly Parallelizable
While the *steps* are sequential, the computations *within* a single mini-batch are **massively parallel**:

* **Matrix Operations**: Evaluating a mini-batch of data (e.g., 32, 64, or 512 samples at once) involves large matrix multiplications and vector additions. 
* **GPU Acceleration**: GPUs (Graphics Processing Units) contain thousands of cores designed precisely to perform thousands of matrix operations simultaneously. Instead of looping through samples one by one, a GPU processes all samples in a mini-batch concurrently in a single parallelized operation.

---

## 3. Distributed SGD (Multi-GPU & Multi-Node Parallelism)
When datasets or models are too large for a single machine, **Distributed SGD** scales parallel processing across multiple hardware units:

* **Data Parallelism**: 
  1. The model is replicated across multiple GPUs or computers.
  2. The dataset is split up, and different GPUs compute gradients for different mini-batches **in parallel**.
  3. The GPUs synchronize (using tools like All-Reduce) to combine their gradients and update the shared model weights before moving to the next batch.
* **Model Parallelism**: For massive models (like billion-parameter LLMs) that cannot fit into a single GPU's memory, different layers or sections of the neural network are split across different GPUs, processing data in a pipeline.

---

## Summary
* **Can you run SGD steps in parallel?** No, because each step depends on the previous weights.
* **Can you make SGD fast using parallel processing?** Yes! By using **mini-batches** and **GPUs**, all the data points within a single batch are processed in parallel.

# Is Stochastic Gradient Descent (SGD) More Time-Consuming?

> [!NOTE] Short Answer
> **No, Stochastic Gradient Descent (SGD) is significantly *less* time-consuming** than standard Batch Gradient Descent in terms of real-world training time, especially as datasets grow larger.

---

## 1. Frequency of Weight Updates
* **Batch Gradient Descent**: Processes the **entire dataset** to compute just a single weight update. If you have millions of training examples, the model must evaluate all rows before taking even *one* step down the error slope.
* **SGD (Mini-Batch)**: Splits the dataset into $R$ smaller partitions (mini-batches). It updates the weights **after every single mini-batch**, meaning it updates its parameters $R$ times per full pass over the data rather than just once. The model starts learning and correcting mistakes much earlier.

---

## 2. Computational Effort Per Step
* **Batch GD**: Calculates the gradient across all data points at once, making each individual iteration computationally heavy and slow.
* **SGD**: Computes gradients on small chunks of data ($\mathcal{D}_r$), making individual steps lightning-fast and easily parallelizable on hardware accelerators like GPUs.

---

## 3. Time to Convergence
* **Batch GD** spends a massive amount of time computing exact gradients for every single data point before moving an inch.
* **SGD** reaches an optimal or near-optimal solution much faster in wall-clock time because frequent, approximate updates get the model close to the minimum long before Batch GD finishes its first few heavy iterations.
