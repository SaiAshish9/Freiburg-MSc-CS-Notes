
## 1. Mathematical Formalisation of Context Sensing

Context-aware computing models the real world through stochastic processes where system states are inferred from incomplete and noisy sensor observations.

### A. The Universe vs. Observable States

The universe consists of a continuous random process of internal states:  

$$X(t) = \{x_1(t), x_2(t), \dots, x_N(t)\}$$

- **Problem 1 (Partial Observability):** Only a minute fraction of the global state space is observable at any given time.
    
- **Context Definition (**$X'$**):** A very small, observable subset of the global internal process:  
    
    $$X'(t) = \{x_1(t), x_2(t), \dots, x_{N'}(t)\}, \quad \text{where } N' \ll N$$

### B. State-Dependent Measurement Model

The state-dependent process of all possible measurements in the universe is given by:  

$$Z(t) = \{Z_1(t), Z_2(t), \dots, Z_M(t)\} \triangleq F_{\text{Global}}[X(t)]$$

- **Problem 2 (Sparse & Noisy Data):** Real-world sensor measurements yield only a tiny subset of possible observations.
    
- **Actual Measurement Vector (**$Z'$**):**  
    
    $$Z'(t) = \{z_1(t), z_2(t), \dots, z_{M'}(t)\}, \quad \text{where } M' \ll M$$

## 2. Information and System Models

### A. Mapping Observations to States

A context-aware system models the probability distribution of an internal state $x \in X'$ based on an observation vector $z \in Z'$ via an observation function $f(z)$:

$$f(z) \sim P(x \mid z)$$

### B. Core Context Processing Tasks

1. **Variable Estimation:**  
    
    $$\hat{x} = f(z)$$
    
    _Estimating continuous parameters (e.g., heart rate, stress levels, core temperature)._
    
2. **State Discrimination / Classification:**  
    
    $$C_k = f(z)$$
    
    _Categorising sensory input into discrete classes (e.g., distinguishing between walking, sitting, or running)._
    

## 3. Context Representation Models

### A. Temporal Hierarchy

Context exhibits temporal dynamics that can be broken down hierarchically:

```
[Macro Level]    Daily Routine (e.g., Office Work, Travelling)
                         │
[Meso Level]     Activities (e.g., Entering, Greeting, PC Work, Riding Train)
                         │
[Micro Level]    'Atomic' Actions / States (e.g., Walking, Standing, Sitting, Shaking Hands)
```

### B. Main Context Domains ($X'$) and Sensor Sources ($Z'$)

|   |   |   |   |
|---|---|---|---|
|**Domain (X′)**|**Target Concept**|**Example Measurements (Z′)**|**Discrete Classes / State Space (z)**|
|**User Activity**|Physical movement & physical tasks|Motion (IMU), device interaction|Sitting, walking, drinking, eating, climbing stairs|
|**User State**|Physiological & emotional state|Heart rate (ECG/PPG), respiration, GSR|Physical effort, stress level, fatigue, emotional state|
|**Environmental State**|Ambient surrounding condition|Ambient light, sound level/spectrum, temperature|Bright/dark, noisy/quiet, indoor/outdoor, rainfall|
|**Location**|Spatial positioning|GPS/Nav data, Wi-Fi BSSID, Bluetooth beacons|Office, elevator, lecture hall, home|
|**Digital Activity**|Software & cyber interactions|Social media logs, app usage patterns, web browsing|Posts, likes, active typing, screen idle|

## 4. System Modes and System Architecture

### A. Modes of Context Utilisation

- **Active Context Awareness:** The system continuously monitors context and **automatically adapts its behaviour or UI** without explicit user intervention.

- **Passive Context Awareness:** The system **presents information or logs context state** for user retrieval or post-hoc analysis (e.g., sleep episode logs, step counts).
